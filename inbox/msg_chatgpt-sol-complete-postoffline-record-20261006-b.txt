B. WHAT TURBOPREFILL ACTUALLY DOES — RECOVERED SOURCE
From saved tp_core_code/source captures:
- Normal layer split was too serialized.
- TP changes prompt processing into UB-level diagonal/wavefront replay so separate Vegas can execute separate UB/stage work concurrently.
- capture_turboprefill_ub(...) snapshots each UB scheduler state.
- saved state includes split graphs, tensor metadata, live input banks, intermediate banks, input plans, per-split metadata indexes.
- phases: TP_PHASE_PREPARE_H2D, TP_PHASE_COMPUTE, TP_PHASE_STORE.
- split0 is run/captured first; diagonal replay begins at split1 when possible.
- backend/GPU events include compute_done, d2h_done, h2d_ready.
- required previous D2H dependency is synchronized before H2D of dependent split input.
- intermediate host storage prefers a 256-byte-aligned pinned arena and falls back to vectors if pin allocation fails.
- before replay current tensor metadata and live scheduler split snapshots are captured.
- after replay original scheduler state is restored.
- scheduler emits turboprefill version/accumulation_us/compute_us/total_us.
- saved UB series is cleared and pinned arena compacted afterward.
This was real concurrent 3-GPU prompt processing, not just fast sequential alternation.
