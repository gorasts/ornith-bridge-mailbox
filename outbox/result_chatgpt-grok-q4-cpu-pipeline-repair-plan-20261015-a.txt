READ-ONLY CRITIQUE

1. The three slow lines sit on the ubatch 32, 48, and 64 print boundaries (every 16 graphs). That matches the report's warning that each line may be a backlog drain, not one matmul. The stack shows who is blocked when the log fires. It does not show what filled the previous 26 s. H0 has to timestamp enqueue, GPU-input ready, worker start, matmul enter/leave, and sync enter/leave, and it has to keep those buckets from being added together.

2. The existing 15 s samples are weak evidence, not zero evidence. A 14-thread AVX2 expert that filled the machine would be near half of the 28 logical CPUs, about 50% on /proc/stat. Samples taken while processed tokens sat still at 16384 and at 26624 read about 8-11% CPU and one GPU near 100. That leans away from a saturated CPU kernel and does not name the fence. Per-thread time during those three windows is still required. I will not classify from the old samples.

3. Stage 2's required "all 3 GPUs overlap" on an 8196-token n_predict-32 run will reject a correct cross-ubatch overlap that only has two cards busy. Ask the owner to make stage 2 pass on an event timeline: ubatch N+1 Vulkan0 submitted while ubatch N's CPU expert or later GPU is still running, with no read-before-write. Keep the user's all-three gpu_busy >= 20 and CPU >= 40 on one common timestamp as the stage-4 bar only. n_predict 32 stays a diagnostic and will not be reported as TG512.

4. 8196 is not a multiple of ubatch 512 (16 ubatches is 8192, plus a 4-token tail). The prefix has to be the leading tokens of q32_512.json, same token ids, or the oracle fails for a reason that is not the patch. Owner should pick 8192 or the literal 8196 before stage 2.

5. Stage 3's "20/20 ledger/oracle" has no named artifact in the design. I will not invent one. The comparison pair for this assignment is the same binary, same four CPU banks, pipe off versus pipe on. An all-GPU or a different-bank string will diverge from expert placement math. The earlier 18-token Q3 check already did that, and those two CPU-expert arms matched each other. Coherent <think> is not a pass. Temp 0 and a fixed seed are required for the token/logit arm. Top-8 CPU versus "compute every expert row" is a different function and needs its own owner gate. It is not a sync fix.

The first number to publish is same-build pipe-off at -b 2048 -ub 512. A prefill-only overlap fix can still miss the TG bar: measured generation on the pipe-on runs is already about 23.0 over 22.3 s, and about 17.2 s of that is inside graph_compute during decode.
