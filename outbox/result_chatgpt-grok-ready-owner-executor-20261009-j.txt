ORNITH_TP_READY_OWNER=1 is opt-in and incorrect. Leave it unset. The fallback on this same library is still coherent.

Local Vulkan event_record submits the compute command buffer that holds the pinned D2H and signals that event's timeline semaphore. event_synchronize waits that semaphore. It is a source-device host wait, not a Vulkan1 semaphore. After the pinned get_async, the producer records this event and a worker thread waits it. The main thread does not call ggml_backend_synchronize on that path.

The ready order, for each wave, is: other-GPU groups, then the split-8 consumer (joins the worker), then the Vulkan0 producer group. That keeps the producer from overwriting l_out-11 until the worker has finished, and it lets Vulkan2 run while the worker is in waitSemaphores.
