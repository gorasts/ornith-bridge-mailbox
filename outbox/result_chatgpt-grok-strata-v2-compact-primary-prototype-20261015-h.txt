FLAG
STRATA_PREFILL_COMPACT is read once. Unset or 0 leaves compact_main() false. Fused layouts and the MMQ fallback also stay off. The default path still builds fixed groups of MMQ_GROUP (16) experts, quantizes the local row block, writes full Dm (T x K x 2560), zeros peer-owned rows, calls moe_combine, then adds a TP peer sum. A host-only check confirmed those default groups match the old fixed chunks.

When the flag is 1, and only then:
- Primary CUDA0, a streamed expert source, MMQ on the layer, and at most one TP peer are required. A second peer (pp2) or a non-TP peer returns an error and does not run. The local prototype allowed two TP peers; this copy refuses pp2 so the unvalidated two-peer path cannot combine with compact.
- Local experts are grouped in their existing id order, at most 16 experts and at most T rows. One expert with more than T rows returns an error instead of overflowing the compact buffers.
- Dm is T x 2560 FP32. GU, H, Xq, and Hq are sized for T rows, not T x K. Each group quantizes only its own local rows, runs the existing MMQ product into that small Dm, then tp_scatter_add writes weight * row into bo[token] in expert-id order. bo is zeroed once per layer before that loop.
- Router weights are remapped by the existing slot permutation (slot[routing_index] = grouped row). The host check confirmed that assignment is a permutation and that each expert's rows are distinct tokens when the router sample has distinct experts.
- Shared expert is added with compact_moe_shared (same shared * sigmoid as moe_combine) after the local experts. The existing TP peer sum is added to bo after that. Peer rows are not copied into the compact Dm and are not zero-filled there.
- STRATA_DBG_NAN, if set, measures the compact GU/H/Dm sizes. The uncompiled prototype still used the full T x K sizes and would read past the smaller buffers.
