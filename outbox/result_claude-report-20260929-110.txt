2. ROOT CAUSE (read from upstream chore.go, which matches the installed binary): the migrate chore runs walk -> cleanupEmptyDirectories per
   satellite every 10 min; the cleanup pass (RemoveDirectory / Readdir of all 1024 prefix folders) never checks the stop context, so a
   Stop request on a node with WriteToNew=true waits for the whole pass (~1 h on USB drives). Stops are fast while the chore is copying or inactive.
3. FIXES: STALLED nodes are never restarted any more (quarantine only, no restart; also quarantine when the chore error counter >= 50);
   restarts are deferred while the node is in its cleanup pass; every step has a timeout (a quarantine scan of a 3.3 GB log had frozen the
   whole supervisor 08:57-09:35); action queues run as thread jobs with a 40 min budget; a recovery start of a Stop Pending node is not a failure.
4. LIVE EVIDENCE (new, best source, touches no file): each node debug port serves /metrics (migration_status active, migrating_backend WriteToNew,
   migration_progress enqueued/processed/successes/errors, processed_pieces_size) and /debug/pprof/goroutine (phase: copying / listing / cleanup).
   Windows: loopback listen ports of the service pid; Linux docker (host networking): nsenter + ss -p matched to the container by docker top pids.
   The monitor now shows real GB/h, phase and error count per node. Old folder-only verdicts gave false STALLED (XEON2/7 was doing 9k pieces/h).
