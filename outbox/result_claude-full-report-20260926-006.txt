=== 1. ORNITH DIO LOAD FAILURE - ROOT CAUSE + FIX (supersedes my 070 reply) ===
Cause: without mmap the loader puts CPU-side experts (ncm38 ~12.6 GB) in Vulkan PINNED host memory (GTT). amdgpu/TTM cap
GTT at half of RAM by default (GORAST 15957 MiB). Ornith exceeded it -> RADV "Not enough memory for command submission" ->
device lost. Qwen fits under the cap, so it worked. "Bad address" fallback line is harmless (Qwen shows it too).
Fix applied on GORAST (grub): amdgpu.gttsize=28672 ttm.pages_limit=7340032 ttm.page_pool_size=7340032 (GTT now 28672 MiB).
Workaround --no-host loads but is NOT pinned (slower).
Ornith 64K, production flags:            PP      TG     acc
  mmap (production)                    205.8   18.04   75%
  dio + --no-host                      175.8   18.49   79%
  dio PINNED (after GTT raise)         260.5   17.68   69%   <- +27% PP
  mmap + draft n-max 2                 207.2   16.6 (stopped, MTP2 hurts)
Ornith 90K dio pinned: prefill 88K @212 t/s OK, then compute ring timeout on first decode (external draft catch-up) ->
  added amdgpu.lockup_timeout=60000,180000,60000,60000 to grub (NOT yet rebooted). 90K needs a rerun after reboot.
Ornith ncm32 (Qwen-style q8/4096/draft6): VRAM 157 MB free -> spill to GTT -> TG collapsed to ~4.4. ncm38 stays.
