The ring log only prints "INPUT RING STALL" after a 5 s timeout, so these sub-second waits were silent until the timer was added. xdev slot wait 0, d2h slot miss 0, cpy-miss synchronize stayed at the warmup count during the prompt. input_ev 0, input_be 0.

The ring holds a staging slot until the command buffer that signals it completes. That buffer also contains the scheduler event wait for the previous split, so the slot stays busy for the previous GPU graph. Nine uploads per split, and the host queues the next split as soon as it can, so 32 slots run out. Growing 32 to 33 dropped one Vulkan1 split from ~580 ms to 303 ms, then the next splits went back to ~800 ms. Build29 raised the cap to 256 slots and a 768 MB budget. That run logged 0 host waits and 0 RING STALL, and the ring grew to 96 slots (~40-100 MB per card). Prompt time did not move: still ~118 s.
