Read-only feasibility verdict: a modified-source Haswell-optimized CPU backend is feasible as a separate development build, but a safe runtime-only switch is not established. No build, source edit, service launch, GPU change, or benchmark was performed.

Evidence from the preserved audit:
- Host CPU is Xeon E5-2680 v4, 14 cores/28 threads. `lscpu` reports AVX2, FMA, F16C, BMI2 and SSE4.x; AVX-512 is absent. This supports a Haswell-class x86 variant.
- The modified `build-vkfix/CMakeCache.txt` has `GGML_CPU=ON`, `GGML_BACKEND_DL=ON`, `GGML_NATIVE=OFF`, `GGML_CPU_ALL_VARIANTS=OFF`, and AVX/AVX2/FMA/F16C/BMI2 options off. Its runtime-mapped CPU module was generic `libggml-cpu.so`; the original historical executable mapped its own `libggml-cpu-haswell.so`.
- Source exposes `GGML_CPU_ALL_VARIANTS` in `ggml/CMakeLists.txt` (around line 183; dynamic backend variants required). `ggml/src/ggml-cpu/CMakeLists.txt` (around line 376) explicitly rejects `GGML_NATIVE=ON` together with `GGML_BACKEND_DL=ON` and points toward the all-variants configuration. Keep native off for this plugin model. The CPU CMake variant builder enables feature-specific targets; this host can execute the Haswell-level AVX2/FMA path.
- The backend registry’s `ggml_backend_load_all_from_path` calls `ggml_backend_load_best("cpu", ...)` (`ggml/src/ggml-backend-reg.cpp`). `GGML_BACKEND_PATH` adds a backend search path; it is not evidence of an override that safely replaces the already selected CPU backend. The historic Haswell `.so` belongs to a different build/source lineage and ABI compatibility is unproven; do not copy or load it into build-vkfix.
- Preserved prior run report: historic TG128 PP566.000/TG29.074; modified PP563.356/TG24.461. Historic loaded Haswell CPU backend, modified generic. Modified decode SCLK medians were lower on all GPUs, which could result from CPU-side stalls; this comparison does not isolate CPU dispatch as the cause. Report: `outbox/result_chatgpt-sol-decode-actual-clocks-shortpair-20261009-m.txt`.
