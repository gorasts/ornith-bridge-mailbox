**Ranked explanations (hypotheses, not diagnoses).**
1. CPU expert backend/dispatch difference. Four expert layers are explicitly placed on CPU; the historic directory contains an Icelake-specialized backend, while the modified build is `GGML_NATIVE=OFF` and exposes a generic CPU library. The runtime-selected module and per-layer CPU time were not logged. This is the best targeted candidate for a decode-only loss.
2. Modified Vulkan host-upload fallback/synchronization. In `ggml/src/ggml-vulkan/ggml-vulkan.cpp`, `ornith_tp_arena_alloc` is defined at line 17005 and called from the ordinary unpinned `ggml_backend_vk_set_tensor_2d_async` fallback at line 17085 without an `ORNITH_TP_*` enable check; pin release is at line 17350. The patched fallback can therefore affect TP-OFF execution whenever the ordinary async write declines a source buffer. It differs from the historical shared-staging/synchronize path. Existing logs do not show how often this branch runs during decode, so causality is unproven.
3. GPU/CPU run state. It is a material uncontrolled confounder because no clocks, power, temperature or CPU utilization were saved. The similar coarse busy means do not rule it out, but provide no affirmative evidence that it caused the gap.
