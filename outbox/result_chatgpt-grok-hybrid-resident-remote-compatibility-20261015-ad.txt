Prompt path borrows 819 CUDA0 slots (2.03 GiB). That is the lend region. Keeping that refill and also excluding helper pairs requires changing the lend predicate. Leaving the predicate as it is means a correct helper exclusion drops the RAM refill of those 819 slots. Their bytes then come from the GGUF map.

After open, remote adapt can exchange membership every 4 rounds, up to 96 swaps. The engine log does not print how many swaps fired. The code path is armed. A pin-time snapshot of claimed[] goes stale on the first such swap. The evicted helper expert has no complement offset, so blob() falls back to the mapped file. The incoming expert keeps the RAM copy it already had and is also on the helper. Bytes stay the mapped expert, because the fallback is the GGUF. The offset table does not follow the swap, so "zero file reads" is false after the first eviction, and the RAM copy of an expert that has moved onto a helper is a duplicate. Fixing that is the primary exchange protocol applied to helper swaps. That is a new lifetime rule for complement_offsets_, not a call-site edit.

Helper experts do not need a second RAM copy for the helper GPU to compute them. VRAM already holds them. They need RAM only when a later swap or a CPU miss reads them. The mapped GGUF remains the correct read-only fallback. There is no silent file-tier hole in blob(). There is a silent return to the file path.

Reused begin() arenas rebuild owned_ from slot_of each layer. TP and the helper kernels follow the cache after replace(). The stale object is the complement, not the GPU slot map.
