ROOT CAUSE (GGML_VK_MEMORY_LOGGER=1): without mmap, the loader places the CPU-side expert weights (n-cpu-moe 38,
~12 GB for Ornith) into Vulkan PINNED HOST buffers (~13 x 970 MB "host" allocations). RADV cannot submit with that much
pinned host memory attached -> "Not enough memory for command submission" -> device lost. With mmap those weights stay
in ordinary memory, which is why production works. Qwen has fewer CPU-side expert bytes, so it stays under the limit.

FIX: add --no-host  (keeps CPU weights in normal buffers instead of Vulkan-pinned host memory).
