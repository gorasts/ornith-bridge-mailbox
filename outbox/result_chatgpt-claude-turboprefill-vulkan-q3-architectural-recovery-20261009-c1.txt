2. ROOT CAUSE OF NO PIPELINE OVERLAP ON VULKAN
- ggml-vulkan.cpp ggml_backend_vk_cpy_tensor_async returns false whenever src and dst are on different VkDevices ("Async copy only works within the same device").
- ggml_backend_sched then calls ggml_backend_synchronize(src) and does a blocking copy at every stage boundary. llama.cpp's native pipeline parallelism (enabled: "pipeline parallelism enabled", sched copies = 4) therefore runs fully serial on Vulkan.
- The TurboPrefill port in this tree only replays splits 1..N-1 diagonally. It runs every UB's split 0 serially during capture and blocks the CPU on event_synchronize between phases. Even working perfectly it has a low ceiling: b8192 TP-active gave 699.5 (+3.9%).

3. THE FIX (isolated tree ~/c1-xdev, opt-in env GGML_VK_XDEV_ASYNC=1)
Patch: ~/ornith-q3-c1-prodref-20261009/c1_xdev_patch.py and ggml-vulkan.c1-xdev-v2.diff. It changes only ggml-vulkan.cpp. Cross-device async copy:
- The src queue copies the tensor into a host-visible staging buffer of the src device and signals a timeline semaphore there.
- A relay thread per device pair waits on it, memcpy's into a host-visible staging buffer of the dst device, and host-signals a timeline semaphore on the dst device.
- The dst queue waits on that semaphore GPU-side, then copies into the scheduler's input copy. The scheduler thread never blocks.
- An 8-slot ring per edge is protected by a dst-done timeline semaphore. Copies under 1 MiB (token generation) keep the old blocking path.
Two correctness traps were found and fixed. Both reproduced deterministically before the fix:
- (a) Prompt corruption. Once the CPU runs ahead, the CPU-computed token-embedding split (pinned COMPUTE host buffer) is overwritten by the next UB before GPU0 executes its deferred upload. The model then misread the ledger: output diverged at token 137 and ran to the 8192 limit. Fix: large non-weight host-source copies are synchronous while async is on. This stalls only stage 0.
- (b) TG -16%. v1 imported user memory into both devices (VK_EXT_external_memory_host = amdgpu userptr). The kernel then revalidates userptr pages on every later submission, so TG fell to 27.1 even after prefill. Fix: driver-allocated staging plus the relay memcpy. TG recovered to 32.1.
Bisection (first 160 tokens vs production): async off = identical; async with CPU waiting for each src copy = identical; full async before fix (a) = diverges at 137; after fix (a) = identical.
