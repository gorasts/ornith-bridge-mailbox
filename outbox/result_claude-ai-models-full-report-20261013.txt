=== 1. ORNITH 1.5 35B-A3B Q3 (production model) - NEW PRODUCTION CONFIG "v3mx2" ===
Promoted 13 Oct ~11:30 with the operator's go. ornith-server is STOPPED by operator choice (enabled = starts on boot); it is restarted
only when Gorast says.
What it is: llama.cpp Vulkan + three changes of mine:
 a) xdev v3 cross-device async copy (GGML_VK_XDEV_ASYNC=1): the source GPU copies to host-visible staging + timeline semaphore, a relay
    thread memcpys to the destination staging and host-signals its timeline, and the destination waits GPU-side. This gives real
    pipeline parallelism across the 3 cards (run with TURBOPREFILL=0, -b 32768 -ub 1024). Root cause it fixes:
    ggml_backend_vk_cpy_tensor_async returned false across devices, so the scheduler blocked. The old TurboPrefill was never active
    in production (it needs n_tokens >= 2*ub per decode AND pipeline_parallel).
 b) v3m async readback arena (GGML_VK_ASYNC_READBACK=1): the MTP draft reads t_h_nextn from the last GPU every ubatch, but
    ggml-vulkan registers pinned host memory on devices[0] only. The non-pinned fallback forced a full ggml_vk_synchronize per
    ubatch (proved with gdb). Fix: a per-backend host readback arena, with the memcpy deferred to synchronize.
 c) MTP draft shisa12k-mtp-standalone.gguf (1.57 GB) on the x16 card (-devd Vulkan1), layer split -ts 1.05,0.85,1.1 (operator's
    idea: shift layers so the x16 card runs the MTP head; over x1 the draft's serial mask upload was the cost).
Command (/etc/ornith/threecard.cmd):
 /usr/bin/env TURBOPREFILL=0 GGML_VK_XDEV_ASYNC=1 GGML_VK_ASYNC_READBACK=1 MESA_VK_DEVICE_SELECT=1002:687f
