PATCHES THAT DID NOT MOVE THE SCORE

All of these are in the dirty c1-xdev tree only. Production was not replaced.

- ORNITH_PIPELINE_OT keeps pipeline when -ot is set. Confirmed on every scored async run: "pipeline parallelism enabled (tensor overrides kept)", pipe 1, kept 1. Sched copies = 4. Reserve took 54.67 ms on the surviving log.
- --no-op-offload keeps the expert matmul on the CPU backend. Without it, item 2 above.
- ORNITH_SCHED_COPIES is set to min(4, n_batch/n_ubatch). At 2048/512 that is 4. At 2048/2048 it would be 1. The scored runs stayed at 4.
- One-time expert-id memcpy ("ornith full expert") was added so the CPU MUL_MAT_ID would not synchronize the GPU to read expert ids. The surviving build29 log has zero "ornith full expert" lines. The 6-10 s CPU wait described before these builds is still present, and it is larger. See the three CPU splits below.
- ORNITH_CPU_WORKER=1 returns from CPU graph_compute and signals the GPU later. CPU samples on the scored runs stayed about 8-12%. The four-way flag needs CPU >= 40 and all three GPUs >= 20. four stayed 0. The stall stack is inside ggml_cpu_worker_sync, so the worker did not actually free the scheduler.
- xdev slot pool was raised (reserve 64, grow, wait only when full). xdev edge came up on every scored CPU-offload run. Slot-wait count stayed 0. The edge is not overlap.
- CPU submit parking was turned off. Parked submits were dropping the xdev signal. Turning park off did not create overlap.
- Input ring grew from 32 slots. Build28 proved the old 600-890 ms "slow split" was a ring host wait inside the input loop (copy_ms), with graph_ms about 2 ms after shader compile. The 5 s RING STALL log stayed silent for those sub-second waits. Build29 raised the cap to 256 slots and a 768 MiB budget. The surviving log has zero "input ring host wait" and zero "RING STALL". The prompt did not get faster.
- Flush-before-graph on the scored binary looked for the ring semaphore on the open submission, did not find it (sigs 1, some other semaphore), and returned. Eight "input ring flush miss" lines. One success line, Vulkan0 warmup only. Copies were not submitted ahead of the fat graph on the real prefill.
