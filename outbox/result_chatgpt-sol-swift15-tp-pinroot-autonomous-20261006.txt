ROOT CAUSE IN SOURCE
- ggml/src/ggml-vulkan/ggml-vulkan.cpp around 16065-16124 hard-codes Vulkan host allocation, free, alignment, and max-size to vk_instance.devices[0]. The source contains its own TODO: host buffer type should be device-specific.
- ggml_vk_host_malloc registers the host pointer only in that device's pinned_memory registry. ggml_vk_host_get checks only the source device's registry.
- ggml/src/ggml-backend.cpp around 1155-1166 only selects CUDA host buffer types for the TP arena; Vulkan is excluded.
- TP currently has one shared pinned arena/buffer type, so simply allowing Vulkan there would still allocate/register only for Vulkan0 and would not make the buffer valid on Vulkan1/Vulkan2.
- Therefore removing synchronization or sharing a Vulkan0 VkBuffer handle across logical devices would be incorrect.
