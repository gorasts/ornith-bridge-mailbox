# Same-Vega prefill gap: engine architecture, not a 200-PP hardware ceiling

**The earlier hardware-only ceiling claim was wrong.** Claude measured substantially higher PP on the same three Vega64 host. Different active-model sizes, graphs, quantization and workloads prevent transferring those speeds to Flash-Next. Current evidence identifies Strata scheduling, streaming and kernel work; it does not establish its ultimate hardware limit.

**Owner correction received during this audit:**300MiB free VRAM is a performance guideline, NOT a hard safety floor. AO's300MiB guard is a historical fact, not future policy.322MiB free does not itself block optimization or longer context. Future work must budget actual pending allocations/lifetimes and retain allocation/OOM/illegal-address/hang/reset/AER, host-capacity, watchdog and cancellation protections. No thermal software kill or hardware control change. No GPU run, compilation, engine source/config/service change occurred in AP. A separately requested local bridge spam repair interrupted the audit; it did not touch the inference host.

## Three-stage first-pass resource model — no GPU run

Read actual GGUF tensor headers only and pack index; no payload benchmark. NativeDense eligibility yields300 projection matrices,2018.882MiB, matching AO's runtime. Packed non-native weights add1466.785MiB; output Q5_K head497.314MiB is separate, embedding322.07MiB stays mapped on host, MTP adds~159MiB on its device. “~2GB dense” alone therefore undercounts fixed GPU weights. Header offset-span rounding is at most alignment padding; stage estimates are not an allocator fit certificate.

Source stage trimming is opt-in (generate.cpp:2214–2247); without it, stages duplicate the full dense model. PLE tensors remain on every device, primary retains foreign routers for lookahead, last stage holds head/draft. session.cpp:54–70 is stage-aware for recurrent layers but duplicates shared work buffers. Resident raw QSA KV is~20.625MiB per QSA layer,247.5MiB total at20480 cells; indexer/workspace/graph buffers and draft KV are additional. Full131K host history~1.55GiB is not all GPU KV.

These are service envelopes; overlap/shared links change wall. Direct HIP P2P support was not queried or assumed.

With8 chunks, three perfectly balanced equal-speed compute stages alone have ideal speedup3×8/(8+2)=2.4 before transfers, expert reloads, imbalance and scratch;24/12/12 bottleneck≤2× and32/8/8≤1.5× before bubbles. More seriously, helper stages must stream their missing weights over x1. An illustrative9GiB missing per16-layer helper stage, reloaded8 times, costs193–322s of x1 service, already larger than AO145s prefill. This is a stated scenario, not measured traffic. Layer-major reuse could change that break-even; naive layer splitting is not an established win.

Existing source already has asynchronous stage handoff via two host buffers/thread (prefill.cpp:3428–3446), not a missing generic “turn on pipeline” flag. AH generate.cpp:1621–1627 explicitly rejects layer split under the full RAM-mirror mode. Safe stage ownership/cache/mirror adaptation, device timelines and allocation budgets are prerequisites. It is NOT a drop-in Claude binary or TP flag.

## Bounded decision

No demonstrated low-risk single patch currently promises gains beyond the18.6% stream-gap ceiling. **Choose one cross-chunk expert-reuse prototype source gate**, as separately authorized by AQ, ahead of a three-device layer rewrite or blind TP3. Measure actual repeated expert IDs/bytes from current Source/issuer counters first; then retain weights across two ordered chunks only if a bounded residual/issuer lifetime design preserves GDN/QSA/PLE/HC and restores every decode cache. Do not promise a speedup before those counts and dependencies. Existing32K mirror TG25.59,7.5K TG27.66 and static correctness are the comparison baseline.

If that source gate exposes a fundamental multi-subsystem rewrite, return its exact blocker and one smaller implementation, rather than run a parameter sweep. Any future GPU validation belongs to AQ's separate finite gates, with actual allocation capacity and genuine fault protection; AP itself stops here. No90K run, promotion or engine change in this review.
