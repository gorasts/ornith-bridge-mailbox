TRUE TURBOPREFILL is a SEPARATE architecture. Public https://github.com/sergey-automation/TurboPrefill uses diagonal microbatch replay across LAYER-SPLIT GPU stages. Current STRATA_TP=1 runs ALL48 layers on main PCI05 GPU and lets first x1 CUDA1 helper compute some of the same layer's resident expert rows, returned as weighted sums; second x1 CUDA2 is decode cache only. Therefore setting TurboPrefill on current expert-parallel shape CANNOT create a pipeline. A real Strata port would require splitting consecutive dense layers, stage-owned GDN/QSA+state, per-stage expert caches/dense weights, 2-3 stage GPU handoffs and microbatch scheduling. Existing Stage AH resident CPU mirror explicitly forbids --layer-split; ownership needs new correct implementation. x1 crossings may be smaller than current per-layer TP transfers (1-2 boundaries per microbatch instead of FP16 input+sum per 48 layers), but peers each only had 567/420MiB VRAM free with existing cache: stage dense allocations force shrinking expert caches. Need calculate bytes/VRAM break-even before code. Split likely affects decode negatively due serial x1 handoffs every token.
